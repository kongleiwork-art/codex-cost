# 系数是怎么测出来的

`results.jsonl` 是全部 421 次受控调用的原始记录（23 个实验组）。
`quota_probe.py` 是跑这些实验的框架。

## 为什么必须做受控实验

真实开发中几个变量高度共线，观测数据永远拆不开：

```
cached ↔ 请求数    r = +0.949
output ↔ 请求数    r = +0.879
cached ↔ output   r = +0.825
```

在 219 个真实会话上，"总 token""cached""output""请求数"四个口径的离散度全是
44–45% —— 不是巧合，是它们互为线性组合。只有固定其余条件、单独改一个变量才能分开。

## 分辨率是硬约束

`used_percent` 在 48,001 个历史样本里**全部是整数**。单个任务量不出 1.7%。
只能靠跨窗口累积拟合 —— 像只显示整公里的里程表：测不了一趟短途，
但能测准"每公里耗多少油"。

所以每个实验组必须一直跑到 Δ 足够大（本实验统一 5% 或按预算跑满），
Δ 小的组结论不可信。

## 已知的坑

- **`max−min` 会系统性低估 Δ。** 样本少时尤其严重 —— 而最贵的模型恰好跑不了几次
  就撞预算，于是被低估得最狠。早期 `astra` 测出 2.45×，真实值在 3.4× 以上。
- **打满 100% 的窗口必须剔除。** 额度停在 100 但 token 继续涨，Δ 被截断。
- **并发会污染归因。** 历史会话有 35% 时间重叠；跑实验时不要同时用 Codex。
- **窗口重置可能发生在实验中途**，要按重置点切段，别跨段算 Δ。

## 复现

```bash
python3 quota_probe.py plan                    # 看实验矩阵
python3 quota_probe.py run --yes --cell control --trials 20 --budget 6
python3 quota_probe.py analyze
```

先跑 `control` 组：如果换算率和 README 里的对不上，说明官方改了计量规则，
其余数据不能和新数据混用。

**实验会真实消耗你的订阅额度。** `--budget` 是上限保护，到点自动停。
