## 一句话

在 Mac 刘海里看 Codex 额度，并知道这些 token 换个模型要花多少。

## 三层，按顺序做

| 层 | 回答的问题 | 现在有什么 |
|---|---|---|
| **看得清** | 我用了多少、还剩多少、花在哪 | 5 小时 / 周额度、独立额度池、成本构成、换模型对照、阈值提醒、历史用量 |
| **算得准** | 每种 token 到底值多少额度 | 671 条受控试验、`research/refit.py`、系数 v4 |
| **用得省** | 怎么少花额度 | 本地路由规则、刘海任务入口、Codex 路由钩子（未安装） |

下一层建立在上一层之上。「用得省」的功能要先证明能省下多少，再继续投入（见阶段 3 的门槛 G1）。

## 工作约定

- **从文档出发**：任务先写进这里再做；做完把状态改掉。临时想法先放进「待你决定」或「暂不做」，不直接开工。
- **一个任务一个分支**：`feat/`、`fix/`、`exp/`、`docs/` 开头，从最新的 main 开。推送到 main 前等你确认。
- **合并前三件事**：`tests/` 下全部测试通过；改了行为就同步两份 README；隐私扫描（本机路径、邮箱、密钥）。
- **本机全局配置单独确认**：动 `~/.codex`、`~/.claude` 之前单独问；不跳过任何安全检查。
- **实验守则**：你不用 Codex 时才跑；每组都设 `--budget`；距上次对照组超过 3 天、或刚发生过额度重置，先跑 `control`。
- **一段逻辑一份实现**：做不到的（额度解析有 Swift 和 Python 两份）用测试对账。
- **先有数据再建**：值不值得做，先用现有日志回测；像共享黑板那次一样，数据说不值就不建。

## 现状快照（2026-09-15）

### 已发布（main `de9faf4`）

- **额度**：5 小时和每周两个窗口；按周窗口的重置时间区分独立额度池；只认 `limit_id=codex` 的读数；折叠态、菜单栏和提醒看更满的那个窗口；80% / 95% 提醒
- **成本**：新增输入、缓存、输出、每请求四项拆分；同样的 token 换成其它模型要多少
- **历史用量**：Codex、Claude Code、opencode 三个来源，按天、工具、模型汇总；索引保留已删除文件的记录
- **刘海任务入口**：本地规则 + Luna 选模型，在终端开 Codex 交互会话
- **研究**：671 条记录（09-07 ~ 09-14）；sol 系数 v4；astra 缓存费率由 `astra/bigctx` 定下
- **测试**：`test_quota` 6 个、`test_router` 19 个、`test_usage` 6 个

- 全部历史里约 11 亿 token 的 Codex 请求没有记录模型名（早期会话、自定义 provider）

## 暂不做

- **拦截网络请求改模型**：订阅登录不支持，可能违反服务条款；每次换模型缓存都会失效，反而更贵
- **Claude Code 的额度系数**：要在 Claude 那边另做一整套受控实验
- **Cursor、Gemini、网页和桌面聊天的用量**：本地没有 token 记录
- **应用签名和公证**：需要付费的 Apple 开发者账号

## 风险

- **Codex 日志格式会变**：这次就多出了 `base_model_inference` 限额。遇到新格式先补一个固定样本，再改代码
- **额度解析两份实现**：Swift 和 Python 靠 `test_quota` 对账，改一边必须跑测试
- **系数散在四处**：0.4 做完之前，改系数要同时改 `Budget.swift`、CLI、refit 和两份 README
